Air (Amethyst) Metal Renderer Integration Package
=================================================

What is this?
-------------
An Air launcher (5.0.0 / 48a0202) with the metallum agent built in, enabling native Metal rendering
for Minecraft Java Edition on iPhone/iPad. No Fabric/Forge is required; it works directly with vanilla instances.

Included in this package
------------------------
1. metallum_agent.jar
   - Agent: premain injects PreferredGraphicsApi.getBackendsToTry -> [Metal, Vulkan, GL]
   - Calls ensureSpvcLibraryConfigured early (prevents the Spvc class from loading MoltenVK's stripped symbols first)
   - Automatically detects Fabric: skips injection when Fabric Loader is detected (the bundled mod handles it)
   - MANIFEST: includes Premain-Class/Agent-Class; 178 classes (metallum backend + ASM)
2. MetalUniversal-1.0.4.jar (Fabric mod; bundled in mods_preload/)
   - The launcher automatically copies it to the instance's mods/ directory on first launch (automatically active in Fabric instances; harmless in vanilla, where it is not loaded)
   - natives replaced with an ad-hoc-signed libmetallum
3. natives/ios/libmetallum.dylib (ad-hoc signed; loaded with DyldLVBypass)
4. natives/ios/libspvc.dylib (full MSL backend, compiled with the SPIRV_CROSS_C_API_MSL C API macro)
5. A new "Metal (metallum)" renderer option in launcher settings (selecting it sets AMETHYST_METAL=1; EGL falls back to auto)

Ready to use: in vanilla instances, the agent injects automatically; in Fabric instances, the bundled mod is
automatically installed in mods, and the agent yields when it detects Fabric. Neither setup requires manual configuration.

Installation
------------
1. Install this IPA with iloader (installing over the same bundle ID preserves game data).
2. Enable JIT: attach StikDebug (or use pymobiledevice3 debugserver lldb --launch).
   In launcher Settings -> Debug, enable:
   - Use Universal StikDebug Script
   - Keep attached to StikDebug
   (The third option, Skip 'Waiting for JIT' dialog, is optional; enable it if JIT gets stuck spinning.)
3. Launcher -> Game Settings -> Renderer -> select "Metal (metallum)".
4. Start the game.

Measured performance (iPhone 17 Pro / A19 Pro / iOS 27.0)
---------------------------------------------------------
- Metal: stable 105+ FPS at 32 chunks (native)
- Zink: about 50 FPS at 32 chunks (GL-on-Vulkan translation layer)
- MoltenVK: single-digit FPS (unusable)

Frequently asked questions
--------------------------
Q: Metal is missing from the renderer list?
A: Confirm that libs/metallum_agent.jar exists (it is included in this package). The renderer option is under Game Settings.

Q: Is the game using OpenGL (log: Using graphics backend OpenGL)?
A: Confirm that 1) Metal is selected as the renderer, 2) the log contains "[JavaLauncher] Metal renderer selected:
   AMETHYST_METAL=1", and 3) the log does not contain "defineMetallumClasses failed" (this occurs when
   --add-opens=java.base/java.lang=ALL-UNNAMED is missing; fixed in this package).

Q: missing code signature?
A: DyldLVBypass is required (enable both StikDebug options), and the dylib must be ad-hoc signed (the natives
   in this package are signed). Without the bypass, AMFI rejects unsigned dylibs.

Q: Does spvc_context_create_compiler return -4 Invalid backend?
A: The loaded libspvc is missing the MSL backend (the C API macro must be SPIRV_CROSS_C_API_MSL, not
   SPIRV_CROSS_ENABLE_MSL). This package includes full natives; verify the build if replacing them yourself.

Q: Is game data preserved when installing over an existing app?
A: Installing over the same bundle ID preserves the data container (Documents: saves/mods/settings/logs).
   It is recommended to back up Documents before upgrading.

Q: Does the agent conflict with Fabric instances?
A: Starting with v23, the agent automatically detects Fabric Loader at startup and skips injection when Fabric is detected;
   the official MetalUniversal Fabric mod (mixin) takes over. The agent injects only in vanilla environments.
   Both modify the same methods (getBackendsToTry/caption); only one is used at a time.

Log locations
-------------
Launcher -> Debug Logs; or Documents/instances/default/logs/latestlog.txt
Crash reports: Documents/instances/default/crash-reports/
